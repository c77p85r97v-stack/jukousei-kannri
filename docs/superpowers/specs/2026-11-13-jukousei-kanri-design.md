# PC講習会 受講生管理システム 設計書

作成日：2026-11-13
状態：レビュー待ち

## 1. 目的と前提

### 目的
Google スプレッドシート（曜日シート9枚＋第N回シート＋解約・移動シート）で行っている PC 講習会の受講生管理を、Web システムに置き換える。

- **速いこと**：画面の表示・保存がスプレッドシートより明らかに速い。
- **壊れないこと**：関数・セル範囲参照をなくし、誰がどう入力しても集計や名簿がずれない。

### 今の仕組みで起きている問題（2026年度ファイルで確認）
- 名簿の自動生成が `月!$D$2:$F$16` のような固定のセル範囲に依存しており、行の挿入や移動でずれる。
- 同じ計算の式が食い違っている（「月」シートのタイピング伸びが `=G2-X2`、ほかのコマとひな形は `=X2-G2`。「火2」AB4 が `水2!I70` を参照）。
- 備考が自由記述のため、`COUNTIF("*補講*")` などの集計が表記ゆれで狂う。
- 第N回シート9枚が重い配列関数（FILTER / VSTACK）で全コマを引くため遅い。

### 決まっている前提
| 項目 | 内容 |
|---|---|
| 利用者 | GA 全員（入力）、チーフ・副チーフ・職員（管理者） |
| 端末 | 主に PC のブラウザ |
| 規模 | 1年度あたり受講生 約420人、コマ9つ、1コマあたり班 約7つ |
| 回 | **第0回〜第8回の9回**（年度ごとの設定で変更可）。**第0回は自由参加**：出席をつけるだけで、欠席・タイピング・クイズ・補講なし。集計では参加人数だけ別に数える |
| タイピング | **第1回〜第8回**（第0回は行わない。年度ごとの設定で変更可） |
| クイズ（確認テスト） | **第1回と第8回**（年度ごとの設定で変更可） |
| GA の編集範囲 | **すべての班**を編集できる（操作履歴に残る） |
| 画面の色 | **薄紫**基調（勤怠システムの紺と区別する） |
| 既存データ | 2026年度データは**取り込まない**。次の講習から新システムで開始 |
| 環境 | **本番のみ**（テスト環境は作らない）。試用後は管理画面の「初期化」で記録を消して本番運用に入る |
| 補講 | **欠席者の行で「補講」を押し、受ける場所を1つ選ぶだけ**（5章・3章参照） |

## 2. 構成

```
PC のブラウザ
   │  画面（HTML / CSS / JS）……… Vercel 静的配信
   │  /api/* ……………………………… Vercel Functions（Node.js）
   ▼
Neon（Postgres）  ── 毎日 3:00 バックアップ ──► Vercel Blob（非公開）
```

- 書き方は勤怠システム（npas-attendance）に揃える：素の HTML / JS、Node.js の API、SQL のマイグレーションファイル。
- 勤怠システムから流用するもの：署名付き Cookie のログイン、操作履歴、CSRF 対策（`X-Requested-With` ＋同一オリジン）、バックアップ・復元、管理画面のタブ構成。
- データベース接続は `@neondatabase/serverless`。書き込みは必ずトランザクションで行う。
- 環境は**本番の1つだけ**。試しに使ったデータは管理画面の「初期化」で消す（7章）。
- リポジトリは **非公開（private）** にする。受講生の実名を含むファイルはリポジトリに入れない（`.gitignore` で除外）。

## 3. データの持ち方

表示用の数字（人数・継続率・伸び・名簿）は**表として持たず、表示のたびに SQL で計算する**。関数やセル範囲が存在しないので、ずれようがない。

| 表 | 主な列 | 制約 |
|---|---|---|
| `terms`（年度） | id, name（例：2026年度PC講習会）, rounds（例：0〜8）, typing_rounds（例：1〜8）, quiz_rounds（例：{1,8}）, indiv_labels（個別補講①〜⑦の基本の曜日と時間）, initial_count（初期受講生数。空なら登録されている受講生の人数。最初の回の前に解約した人も含む）, active | active な年度は1つ |
| `slots`（コマ） | id, term_id, code（月・火1・火2・水1・水2・木1・木2・金1・金2）, sort | (term_id, code) 一意 |
| `staff`（スタッフ） | id, name, role（`ga` / `admin`）, pin_hash（管理者のみ）, failed_logins, locked_until, active | name 一意 |
| `groups`（班） | id, slot_id, ga_id（担当 GA）, sort | (slot_id, ga_id) 一意 |
| `students`（受講生） | id, term_id, name, kana, nickname, group_id（入学時の班）, created_at | — |
| `records`（記録） | id, student_id, round, attendance（出欠区分）, typing（数値・空可）, quiz（整数・空可）, note（メモ）, version, updated_by, updated_at | (student_id, round) 一意。typing は 0 以上でタイピングの回だけ、quiz は 0 以上の整数でクイズの回だけ入力可 |
| `makeups`（補講） | id, student_id, round, place（`他班` / `個別` / `未定`）, host_group_id（他班のときの受け入れ先の班）, failed（できなかった＝×）, version, created_by | (student_id, round) 一意。他班のときは host_group_id 必須 |
| `withdrawals`（解約） | id, student_id, from_round（未受講回＝この回から受けていない）, reason, manager_checked_by（受講生管理の確認者）, staff_confirmed（職員確認）, created_by | student_id 一意 |
| `transfers`（コマ移動） | id, student_id, from_group_id, to_group_id, from_round（移動後に受講する最初の回）, manager_checked_by, created_by | — |
| `audit_log`（操作履歴） | id, at, operator_id, action, target_table, target_id, before_json, after_json | — |

### 出欠区分（`records.attendance`）
自由記述をやめ、次から選ぶ。メモ欄（note）は自由記述のまま残す。

| 区分 | 今の書き方 | 意味 |
|---|---|---|
| `出席` | タイピングの数値 | 受講し、記録あり |
| `記録なし` / `時間切れ` | 記録なし / 時間切れ | 受講したが数値が取れない |
| `欠席` | （欠席） | 欠席。まだ補講の場所を決めていない |
| `欠席・補講予定` | △ | 「補講」で場所を選ぶと**自動で付く**（手で選ばない） |
| `欠席・補講できず` | × | 「できなかった」を押すと**自動で付く** |
| （空） | 空欄 | 未入力 |

### 補講の流れ（シンプル版）
1. 元の班の GA が、欠席者の行で「補講」を押し、**受ける場所を1つ選ぶ**：○曜の○○の班／個別／未定。→ `makeups` を1件作り、出欠区分は自動で `欠席・補講予定`（△）。
2. 「○○の班」を選んだ場合、その回の**補講先の名簿に自動で載る**（「補講で来る人」として表示）。
3. 補講先の GA がその人のタイピングを入れると、**受講生本人の記録（その回の1件）に保存される**。元の班の画面でも同じ記録が見え、補講の状態は自動で「済」になる。別の場所に書き写す作業はない。
4. 「個別」「未定」の場合は、決まった人・実施した人が、補講一覧または元の班の行から記録を入れれば「済」になる。場所はあとから何度でも変えられる。
5. 補講できなかったときだけ「できなかった」を押す → 出欠区分は自動で `欠席・補講できず`（×）。
6. 振替（欠席の前に、別の班で受けることが決まっている場合）も同じ操作で扱う。

補講の状態は持たず、毎回次のように決める：記録に出席系の区分が入っていれば **済**、`failed` なら **できず**、それ以外は **予定**（場所が未定なら **未定**）。

### 名簿の決まり方（第 N 回・班 G の名簿）
1. 受講生の**その回時点の班**：コマ移動のうち `from_round <= N` で最も新しいものの移動先。移動がなければ入学時の班。
2. その回時点の班が G で、**解約していない**（または解約の `from_round > N`）受講生。
3. ＋ `makeups` で第 N 回の受け入れ先が G（`place = 他班`、`failed` でない）の受講生を「補講で来る人」として追加。
4. その回に別の班へ補講に出ている自分の班の受講生は、名簿に残したうえで「補講先：〇〇」と表示する。
5. 個別・未定の受講生は、管理者画面の補講タブに一覧で表示する（名簿は作らない）。

### 集計の定義
| 指標 | 計算 |
|---|---|
| 班人数 | 名簿の決まり方 1〜2 の人数（補講で来る人は含めない） |
| 解約者数 | `withdrawals` の件数（コマ別、未受講回別） |
| 継続率 | (初期受講生数 − 解約者数) ÷ 初期受講生数 |
| 継続率（最初の回から未受講の解約を除く） | (初期受講生数 −（解約者数 − 最初の回から未受講の解約者数）) ÷ 初期受講生数。旧スプレッドシートの「継続率（第1回未受講者は除く）」と同じ計算。両方を表示する |
| 解約率 | 解約者数 ÷ 初期受講生数 |
| 各回の受講率 | その回の在籍者のうち、出欠区分が出席系（`出席` / `記録なし` / `時間切れ`）の人 ÷ その回の在籍者 |
| コマ移動数 | `transfers` の件数（移動元・移動先別） |
| タイピングの伸び | **第1回の記録 − 第8回の記録**。記録は秒数で、短いほど良いので、正の値＝改善。第1回に数値がない場合は、数値がある最も早い回を使う（今の「月」シート7行目と同じ扱い） |
| クイズの伸び | 最後のクイズの回の点 − 最初のクイズの回の点 |
| 班の伸び平均 | 班内で両方の値がそろっている受講生の、伸びの平均 |

> 注：今のシートの「班の伸び率平均」（`SUMIF(伸び>0) ÷ 第9回の記録数`）は、悪化した人を0扱いにしている。新システムでは単純平均にし、あわせて「改善した人の割合」を表示する。

## 4. ログインと権限

- 最初の画面で「GA」か「管理者」を選ぶ。
- **GA**：名前を選ぶだけ（暗証番号なし）。署名付き Cookie、有効期限8時間。
- **管理者**：名前＋暗証番号（数字4〜8桁）。5回間違えると15分ロック。暗証番号はハッシュで保存。
- 権限

| 操作 | GA | 管理者 |
|---|---|---|
| 記録入力（全班） | ○ | ○ |
| 補講の登録・変更・「できなかった」 | ○ | ○ |
| 受講生の検索・閲覧 | ○ | ○ |
| 解約・コマ移動の登録・確認 | — | ○ |
| 受講生・班・コマ・年度の編集、一括取り込み | — | ○ |
| スタッフ・暗証番号 | — | ○ |
| 集計・名簿印刷・CSV | ○（閲覧のみ） | ○ |
| 操作履歴・バックアップ・復元・初期化 | — | ○ |

- 最初の管理者は、環境変数の合言葉（`ADMIN_SETUP_TOKEN`）を使う初期設定画面で作る（勤怠と同じ）。

## 5. 画面

### 共通
- 薄紫基調（ヘッダー・タブは薄紫、文字・ボタンは読める濃さの紫）。勤怠と同じレイアウト（上部ヘッダー＋タブ）。
- 検索エンジンに載らないよう `noindex` を付ける。

### GA 画面
1. **記録入力**（ログイン後すぐ）
   - コマと回を選ぶ（初期値：今日の曜日に近いコマ、最後に入力した回）。
   - 班ごとに表で表示。ログインした GA の班が一番上。
   - 列：ニックネーム・名前・ヨミ・出欠区分・（タイピングの回だけ）タイピング・（クイズの回だけ）クイズ・メモ・補講。
   - タイピングを打って Enter で下の行へ移り、その行を自動保存。保存中は薄く、保存済みは通常表示、失敗は赤。
   - 出欠区分は、タイピングに数値が入ると自動で `出席` になる（手で変えられる）。
   - 「補講で来る人」は班の下に区切って表示。
2. **補講**：記録入力の行の「補講」ボタンを押し、受ける場所（○曜の○○の班／個別／未定）を1つ選ぶだけ。△が自動で付き、補講先の名簿に載る。補講の行には「できなかった」ボタンがあり、押すと×になる（3章「補講の流れ」）。
3. **受講生の検索**：名前・ヨミ・ニックネームで検索し、その人の全回の記録・補講・移動の履歴を表示。

### 管理者画面（タブ）
| タブ | 内容 |
|---|---|
| 名簿 | 回・コマを選んで名簿（補講で来る人を含む）を表示。印刷用レイアウト（出席チェック欄つき） |
| 補講 | 回ごとの一覧。「未定」「予定」「済」「できず」で絞り込み。個別・未定の人の場所変更と記録入力 |
| 解約・移動 | 解約：受講生を検索して選ぶ → 未受講回・理由 → 受講生管理の確認 → 職員確認。移動：受講生 → 移動先の班 → 移動後に受講する回 → 確認 |
| 集計 | 3章の指標をコマ別・班別・回別に表示 |
| 受講生・班 | 年度・コマ・班の設定、受講生の追加・編集、**名簿の一括取り込み**（スプレッドシートから「コマ・GA・名前・ヨミ・ニックネーム」の列を貼り付け → 確認画面 → 取り込み） |
| スタッフ | GA・管理者の追加・無効化、暗証番号の設定 |
| 操作履歴 | 新しい順。操作者・種類で絞り込み。変更前・変更後を表示 |
| データ・バックアップ | 自動バックアップ一覧・ダウンロード・復元、CSV 出力（記録・名簿・集計）、**初期化** |

## 6. エラーと同時操作

- **同時編集**：`records` と `makeups` に `version` を持たせ、保存時に一致しなければ 409 を返す。画面は「ほかの人が先に更新しました」と出し、最新の値を表示する。黙って上書きしない。
- **通信失敗**：未保存の行を赤く残し、「再送」で送り直せる。同じ操作を2回送っても二重にならない（記録は (student_id, round) 一意、そのほかは requestId で重複防止）。
- **入力チェック**：画面と API とデータベース（CHECK 制約・外部キー）の三重。画面の不具合があってもおかしなデータは入らない。
- **解約・移動の取り消し**：削除ではなく取り消し操作として履歴に残す。

## 7. バックアップと復元

- 毎日 3:00（日本時間）に Vercel Cron で全表を JSON にして Vercel Blob（非公開）へ保存。30日分。バックアップの一覧は Blob 自体から作る（データベースが壊れても一覧が残るように、表では持たない）。
- 管理画面から手動バックアップ・ダウンロード・復元。復元の直前に自動でバックアップを取る。
- すべての変更は操作履歴に変更前・変更後を残す。

### 初期化（本番用）
- 管理画面「データ・バックアップ」タブに置く。確認のため「初期化」と入力しないと押せない。
- 消えるもの：記録・補講・解約・コマ移動・操作履歴。
- 残るもの：年度・コマ・班・スタッフ・受講生名簿。
- 「受講生名簿も消す」にチェックすると、受講生と班も消す（年度替わり用）。スタッフと管理者は常に残す。
- 実行の直前に自動でバックアップを取り（種類：初期化前）、「この状態に戻す」で復元できる。

## 8. 確認方法（テスト）

- **自動テスト**（`node --test`、データベースは PGlite＝ブラウザ不要の Postgres）
  - 名簿の決まり方（移動・解約・補講で来る人・補講に出ている人）
  - 補講の流れ（場所を選ぶ → △ → 補講先で入力 → 済／できなかった → ×）
  - 集計（継続率・解約率・受講率・伸び）
  - 権限（GA が管理者専用 API を使えない）
  - 同時編集（version 不一致で 409）
  - 一括取り込み（列ずれ・重複・空行）
  - バックアップ → 復元で全データが一致
  - 初期化（消えるもの・残るもの、初期化前バックアップからの復元）
- **実データでの突き合わせ**（手元のみ・リポジトリに入れない）：2026年度ファイルの名簿を一括取り込み機能で取り込み、記録をテスト用スクリプトで流し込み、新システムの班人数・解約者数・受講率と、スプレッドシートの数字を突き合わせる。
- **画面の確認**：手元の開発サーバーと、公開後の本番でブラウザ操作の通しテスト（GA の入力 → 補講登録 → 受け入れ先の名簿に載る → 解約 → 名簿から消える → 集計）。本番で試したデータは最後に「初期化」で消す。
- **速さの目安**：記録入力画面（1コマ・約60人）の表示 1秒以内、1行の保存 0.5秒以内（本番で計測）。

## 9. 作らないもの（今回の範囲外）

- 2026年度以前の記録の取り込み。
- スマホ専用の画面（PC 前提。スマホでも表示はできるが最適化しない）。
- LINE への自動送信（報告文を作ってコピーするところまで。送るのは手作業。11章）。
- 解約の報告文。
- テスト環境（本番の初期化で代用する）。
- 受講生本人が使う画面。

## 10. リスクと注意点

- **GA は名前を選ぶだけで入れる**ため、URL を知っている人は誰でも GA として受講生の実名を見られる。URL は関係者以外に広めない、`noindex` を付ける、全操作を履歴に残す、で対応する。より強くしたくなった場合は、GA 共通の合言葉を追加できる作りにしておく。
- Neon の東京リージョンがないため、データはシンガポールに置く。
- Vercel の Deployment Protection（Vercel へのログインが必要になる設定）は、GA が Vercel アカウントを持たないためオフにする。


## 11. 追加の決定（2026-11-13）

- **第0回は自由参加**：出欠は「出席」か空だけ。受講率・継続率の計算には入れず、「第0回の参加人数」を別に出す。「1回も来なかった人」は第1回までに解約した人で数える。
- **確認テストは第1回と第8回**、伸び＝第8回 − 第1回。
- **出欠「欠席」は画面では「当日欠席」**と表示する（保存する値は「欠席」のまま）。
- **タイピングを入れたときの自動の出席**：未入力か △（補講予定）のときだけ出席にする。当日欠席と ×（補講できず）は変えない。
- **ニックネーム**：GA が記録入力の画面で書き換えられる（`POST /api/students/:id/nickname`、操作履歴あり）。
- **班の見出し**に「欠席 N人・補講 M人（済 x）」を出す（第0回は「参加 N人」）。
- **個別補講①〜⑧**（`indiv_slots` 表・`makeups.indiv_no / indiv_when / indiv_by`）
  - ①〜⑦：年度の基本（`terms.indiv_labels`、初期値は 水13:00・木13:00・金13:00・月13:00・月16:30・火13:00・火16:30）。回ごとに時間・担当・場所・実施なしを書き換えられる（管理者）。2026年度の実績では第5〜7回で時間が変わる回があったため。
  - ⑧：指定時間外。日時を自由に書く。担当は登録した GA。
  - 「個別補講」タブ（GA・管理者）で回ごとの名簿（元コマ・GA・ナマエ・ニックネーム・状態）を表示・印刷。
- **LINE の報告文**（コピーするだけ。名前はカタカナのフルネーム＝ヨミ）
  - 当日の報告：`お疲れ様です。{GA}です。／{曜日} 第N回の受講生管理が終わりました。／欠席者N名です。／・{カナ}さん（補講：…）／システム入力済みです。`
  - 補講が決まったとき：`{曜日} {GA}班の{カナ}さん（第N回欠席）の補講が、{場所}に決まりました。`
  - 曜日変更（コマ移動）：26振替・移動マニュアルの文面に合わせる。
  - 解約の報告文は作らない。

- **出欠の選択肢（2026-11-13 変更）**：前年度のシートでは「〇」は使われておらず「記録なし」「時間切れ」だけだったため、「出席・記録なし」をやめて「記録なし」にまとめた。画面の表示は「出席」「出席（記録なし）」「出席（時間切れ）」「当日欠席」。古いデータ・古いバックアップの「出席・記録なし」は「記録なし」に置き換える。
- **補講済み（2026-11-13 変更）**：当日欠席して補講（他班・個別）を受けた人は「出席」にせず「欠席・補講済み」として残す（自動。補講予定△の人にタイピングを入れる、または補講のある人に出席系を付けると変わる）。受講率には数え、集計に「うち当日出席／うち補講済み」の内訳を出す。補講を取り消すと当日欠席に戻る（タイピングは残る）。既存データは移行で「欠席・補講済み」に直す。
- **用語（2026-11-13 変更）**：補講の「場所」は画面上「振替先GA」と呼ぶ（前のシートの列名に合わせる）。
- **出欠の呼び方（2026-11-13 変更）**：保存する値はそのままで、画面とCSVでは「欠席」→「当日欠席」、「欠席・補講予定（△）」→「当日欠席・振替済み」、「欠席・補講済み」→「当日欠席・補講済み」、「欠席・補講できず（×）」→「当日欠席・補講できず」と表示する。振替先GAを選ぶと振替済み、タイピングを入れると補講済み。
- **出欠と補講の食い違いを作らない（2026-11-13）**：
  - △は振替先が決まっていれば「当日欠席・振替済み」、未定なら「当日欠席・振替先未定」と表示する。
  - 補講がある人に「当日欠席」や未入力を選んでも△のまま（補講できずなら×のまま）。出席系を選ぶと「当日欠席・補講済み」。補講できずの人に出席系は選べない（補講の「変更」で振替先を選び直す）。
  - 補講済みの人に「できなかった」は押せない。当日出席した人には新しく補講を登録できない。
  - 同じ画面に同じ受講生が2回出るとき（元の班と補講で来る人）、片方を変えるともう片方もそろう。
  - 既存データの食い違いは移行（0005）で直す。
