# PC講習会 受講生管理システム

スプレッドシートで行っていた受講生管理（各回の記録・補講・解約・コマ移動・名簿・集計）を置き換える Web システムです。
関数やセル範囲がないので、行を足しても名簿や集計がずれません。

- 画面と API：Vercel
- データ：Neon（Postgres）
- バックアップ：Vercel Blob（非公開）。毎日 3:00 に自動保存、30日分

設計書：[docs/superpowers/specs/2026-11-13-jukousei-kanri-design.md](docs/superpowers/specs/2026-11-13-jukousei-kanri-design.md)

> **このリポジトリは非公開にしてください。** 受講生の実名が入ったファイル（`*.xlsx`、`private/`）はコミットされない設定になっています。

## 使い方（運用）

### 最初の1回
1. 公開した URL を開くと「初期設定」が出ます。合言葉（環境変数 `ADMIN_SETUP_TOKEN`）と、最初の管理者の名前・暗証番号（数字4〜8桁）を入れます。
2. 管理画面で年度を作ります（例：2027年度PC講習会）。月〜金2の9コマが自動で用意されます。
3. 「受講生・班」タブの「名簿の一括取り込み」に、スプレッドシートの **コマ・GA・名前・ヨミ・ニックネーム** の列をコピーして貼り付け →「確認する」→「この内容で取り込む」。GA と班は自動で作られます。
4. ほかの管理者（副チーフ・職員）は「スタッフ」タブで追加し、「暗証番号を設定」を押します。

### 毎回の流れ
- **GA**：ログイン画面で「GA」→ 自分の名前を選ぶ → コマと回を選ぶ → タイピングを入れて Enter（下の行へ進み、自動で保存）。
- **欠席者**：出欠で「当日欠席」を選び、その人の行の「補講」を押して受ける場所を1つ選ぶ（ほかの班／個別補講①〜⑧／まだ決まっていない）。⑧（指定時間外）は日時を書き、担当は登録した GA になります。△が自動で付き、補講先の名簿に載ります。補講先の GA が記録を入れると、元の班の行にも同じ記録が出て「済」になります。できなかったときだけ「できなかった」を押します（×）。
- **第0回**：自由参加です。来た人に「出席」をつけるだけで、欠席・タイピング・クイズ・補講はありません。集計では参加人数だけを別に出します。
- **ニックネーム**：記録入力の画面で GA がそのまま書き換えられます（操作履歴に残ります）。
- **LINE の報告**：自分の班の見出しの「LINE報告文」、補講の「LINE文」、管理画面「解約・移動」のコマ移動の「LINE文」で文章が出ます。「コピーする」を押して LINE に貼るだけです。名前はカタカナのフルネーム（ヨミ）です。解約の報告文はありません。
- **個別補講**：「個別補講」タブで回ごとに①〜⑧の名簿を見て印刷できます。管理者は①〜⑦の基本の曜日と時間を設定し、時間が違う回・祝日で実施なしの回だけ「変更」で書き換えます。
- **記録閲覧**：GA・管理者とも「記録閲覧」タブで、コマごとに今までのタイピング・出欠・備考・確認テスト・伸びを前のスプレッドシート（曜日シート）と同じ形の表で見られます（見るだけ）。
- **名簿の印刷**：管理者だけ。「名簿（印刷）」タブで、前の「第N回」シートの形（左に補講で来る人、右に班ごとの名簿）を 1コマ＝A4 横 1枚で印刷します。「すべて」はコマごとに1枚ずつ。
- **解約・コマ移動**：管理者が「解約・移動」タブで登録します。名簿と集計に自動で反映されます（名簿の行を手で動かす作業はありません）。

### 回・タイピング・クイズの回
初期設定は、回＝第0〜8回（第0回は自由参加）、タイピング＝第1〜8回、クイズ（確認テスト）＝第1回と第8回です。「受講生・班」タブの「年度の設定」で変えられます。

### 本番を始める前に試したデータを消す（初期化）
管理画面「データ・バックアップ」→「初期化」。「初期化」と入力するとボタンが押せます。
- 消えるもの：記録・補講・解約・コマ移動・操作履歴
- 残るもの：スタッフ・年度とコマ・受講生名簿・班（「受講生名簿と班も消す」にチェックすると名簿も消えます）
- 消す直前の状態は自動でバックアップされ、一覧の「初期化前」→「この状態に戻す」で戻せます。

### 年度替わり
「受講生・班」→「新しい年度を始める」。前の年度のデータは残したまま、新しい年度に切り替わります。

### バックアップから戻す
「データ・バックアップ」の一覧で「この状態に戻す」→「復元」と入力。戻す直前の状態も「復元前」として自動で保存されます。

## 知っておくこと
- **GA は名前を選ぶだけでログインできます。** URL を知っている人は誰でも受講生の名前を見られるので、URL は関係者以外に広めないでください。すべての変更は「操作履歴」に残ります。
- 同じ人の同じ回を2人が同時に書き換えた場合、後から保存した人に「ほかの人が先に更新しました」と出て、最新の内容が表示されます（黙って上書きしません）。
- 集計の「継続率」は2種類出ます。①解約者全員を引いたもの、②第1回から一度も受けずに解約した人（第0回からの解約も含む）を除いたもの（旧スプレッドシートの継続率と同じ計算）。
- タイピングの伸び＝最初の記録 − 最後の回の記録（秒）。プラスが改善です。

## 開発

```bash
npm install
npm test            # API・計算の自動テスト（PGlite＝メモリ上の Postgres を使用）
npm run test:ui     # 画面の自動テスト（Playwright）
DEV_SEED=1 npm run dev   # http://localhost:8787 （架空データ入り。管理者「管理者」／暗証番号 1234）
```

| 場所 | 中身 |
|---|---|
| `src/app.js` | API の入口（ルーティング） |
| `src/routes/` | API（ログイン、マスタ、取り込み、記録、補講、解約・移動、集計・CSV、バックアップ） |
| `src/domain/` | 名簿の計算、補講の状態、集計 |
| `migrations/` | データベースの定義（API の起動時に未適用分が自動で適用されます） |
| `public/` | 画面（素の HTML / CSS / JS） |
| `api/index.mjs`, `vercel.json` | Vercel 用の入口と設定 |
| `tools/reconcile*.{py,mjs}` | 旧スプレッドシートとの突き合わせ（手元専用。データは `private/` に置く） |

## 公開（Vercel）

1. GitHub に**非公開**リポジトリを作って送る。
2. Vercel でそのリポジトリからプロジェクトを作る（Framework Preset は「Other」）。
3. プロジェクトの **Storage** で次の2つを追加して接続する。
   - **Neon**（Postgres）：リージョンは Singapore。`DATABASE_URL` が自動で設定されます。
   - **Blob**：アクセスは Private。`BLOB_READ_WRITE_TOKEN` が自動で設定されます。
4. **Environment Variables** に次を設定する。

   | 名前 | 値 |
   |---|---|
   | `PIN_PEPPER` | ランダムな32文字以上（あとから変えると全員ログインし直し・暗証番号の再設定が必要） |
   | `ADMIN_SETUP_TOKEN` | 初期設定で使う合言葉 |
   | `CRON_SECRET` | ランダムな文字列（毎日の自動バックアップの認証に使われます） |

5. デプロイし、**Settings → Deployment Protection** の「Vercel Authentication」をオフにする（GA は Vercel のアカウントを持っていないため）。
6. URL を開いて「初期設定」から始める。
